# 建模与仿真代码制品通道设计

## 目标

将自然语言需求和可执行代码分开存储、检索、修改和验证，通过稳定标识建立映射。分离的是数据与操作契约，不是为每一步再增加一个LLM调用，也不要求换模型。首次生成代码仍消耗输出token；引用和模块化不能凭空消除这项成本，但后续迭代无需反复传输完整程序。

现有基础：source_id关联用户原话；工程版本、任务epoch和命令围栏；不可变artifact；source.py与文件校验和；参数重放；命名BRep输出；分件依赖计划；失败回执和建模检查。2026-10-25已接入项目级模块注册、精确版本引用、模块检索和顺序依赖增量执行。实施范围和验收证据见[实施记录](code-channel-implementation.md)。

## 三条逻辑通道

| 通道 | 主要数据 | LLM需要看到 | 后端保存 |
| --- | --- | --- | --- |
| 需求与决策 | 原话、范围、参数选择、变更、待确认事项 | 当前有效需求、最新差异、必要原文 | 完整来源和决策记录 |
| 工程代码 | Python模块、参数schema、接口契约、依赖和局部修改 | 模块接口、代码版本、目标片段、补丁 | 完整源码和不可变代码版本 |
| 构建与验收 | BRep、装配位姿、指标、检查、仿真配置和结果 | 当前缺陷、差异摘要及必要证据 | 完整制品、输入和验证报告 |

代码通道操作应是：检索模块、读取接口/片段、提出修改、验证补丁、构建受影响节点、取得结果。避免对话重放、文本摘要或向量命中承担源码的唯一存储职责。

## 模块契约与检索

优先采用普通Python模块和结构化清单，不另造一套CAD语言。拟新增的模块清单包括：

- 稳定module_id和源码code_revision；支持的USD-BRep及运行时身份。
- 输入参数的名称、类型、单位、坐标约定和边界；输出的命名BRep与语义特征。
- 依赖模块与版本、是否消耗/修改输入句柄、输出是否保持独立零件。
- 适用任务/特征标签，已有测试、成功/失败记录和未核验项目。运行成功不等于特征全部验收通过。

数据库保存模块清单、版本、依赖和来源映射；不可变文件存储完整代码；向量库只帮助发现候选。先过滤接口/运行时兼容性，再做结构化和语义检索，再按验证覆盖与相关性排序。模型初次只获取少量候选的接口和证据摘要，选定后按精确版本读取函数或模块。不要用相似度直接决定执行哪个版本，也不要拼接不完整代码片段冒充完整模块。

## 需求与代码映射

拟新增稳定requirement_id、component_id、module_id、code_revision，连接当前source_id、工程版本、artifact_id和验证结果：

`用户来源 → 有效需求/变更 → 零件与特征 → 模块版本及参数 → 构建制品 → 检查/仿真证据`

每条变更明确影响哪些节点，记录为什么修改、基础版本、补丁、输入参数、依赖制品和验证结果。需求失效、代码更新、运行时变化或几何变化按依赖关系传播失效。旧face/edge ID不能直接跨制品沿用；载荷、约束等必须重绑定到当前几何。

## 多轮修改与构建

推荐三类修改，按成本从低到高：

1. 参数变更：只传参数差异，复用代码。
2. 模块局部变更：基础源码哈希+精确替换或函数级补丁，只更新目标版本。
3. 新能力/整体重设计：创建小而独立的新模块，验证后加入模块库，避免每次重写整套装配程序。

补丁应校验基础版本、目标唯一性、语法、参数和接口契约后执行。失败候选与成功版本分开保留，不覆盖当前成功制品。受影响模块及依赖节点重建，其他零件复用BRep；装配位姿改变只重算相应变换。多个机械零件默认保持独立，不以布尔融合代替装配。实际需要的融合属于明确建模步骤。

缓存键应覆盖代码版本、规范化参数、依赖制品、运行时身份和影响结果的设置，不能只靠零件名称。几何、显示网格和分析结果可分别缓存；变形/载荷等结果始终绑定具体几何、网格与工况版本。

### 收纳盒例子

- box_body模块：外尺寸、盒高、壁厚、底厚 → 盒身几何。
- lid模块：长宽、间隙、顶厚、定位边参数 → 盒盖几何。
- assembly节点：盒身/盒盖制品与开盖距离 → 各零件位姿。

盒高40改50：重建盒身；盒盖几何不变；按新盒顶高度更新盒盖位姿，保持原开盖距离。已通过真实CAD模块缓存验收：盒身单独重建，盒盖BRep和局部显示网格复用，盒盖底面高度由70更新为80。单脚本参数重放仍会执行保存程序；只有module_assembly采用上述模块增量路径。

## 仿真通道

同样将分析配置与对话分离：材料、载荷、约束、网格和求解设置采用有版本的结构化配置，尽量复用既有求解器而不是让模型每轮生成求解脚本。配置通过语义对象和几何版本关联零件；几何变更后检查受影响的选择、网格和结果失效。模型主要处理需求差异与结果解释。

## 逐步落地与验收

第一步已实现：当前制品脚本的校验和引用、参数重放，以及base_script_sha256绑定的script_edits精确替换；不匹配、歧义或语法错误不提交CAD作业。按类别处理多调用与输出截断，保留次数上限；记录输出长度/可用的reasoning token统计，不保存原始推理文本。

第二步已实现并验收：项目级模块注册与不可变版本、按标签/参数接口/文本检索、可选本地重排、source_id与requirement_id到模块的映射、精确片段读取及补丁。未建设独立模块向量索引或大量预置模板。

第三步已实现并验收：顺序DAG执行、当前成功制品中的局部BRep与显示网格缓存、位姿分离和依赖变化失效。仿真沿用结构化Study及当前几何绑定校验；完整仿真模板库、求解结果缓存、并行调度和机械装配约束求解尚未实现。

验收指标应包括：首次可见几何时间、端到端时间、每次修改的模型调用数、输入/输出token、源码重复传输量、模块检索命中与实际复用率、实际重建零件数、失败恢复次数，以及关键特征的检查通过率。减少调用不能以遗漏未核验需求为代价。
