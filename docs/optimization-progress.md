## 第一批：模型生命周期与工具准入基础

- 请求拆为准备/保存快照、传输、结算。生产后台使用工作区独立异步 I/O 服务，最多两个在途请求、共享受控 HTTP client；手动离线单步入口保留同步传输，协议校验与结算代码共用。
- task 单在途、同项目决策串行，跨项目按轮转推进；等待原生作业仍可结算。模型等待不再占用协调器线程。
- 纠正、取消、来源遗忘通知 I/O；协调器回收其他路径造成的过期请求，包括项目停止/删除和 head 变化。迟到响应仍经过原有 epoch/head 围栏。
- 关闭停止准入、取消传输、等待清理，暂停未结算请求并保留未知结果说明；启动失败进入清理路径。
- 记录上下文/负载准备耗时、负载字节、工具数量和准入摘要，复用模型回执的实际用量与耗时。
- 工具 schema 缓存不可变序列化模板，阶段裁剪获得独立嵌套副本；每步固定准入快照，并在服务器展开前检查工具名称、顶层允许字段与必需字段，类型/嵌套/命令语义继续由现有 Pydantic prepare 校验。

验证：定向运行 `test_model_io_v2`、`test_tool_admission_v2`、`test_model_tasks_v2`、`test_tasks_v2`、`test_context_efficiency_v2`、`test_agent_orchestration_v2`，共 52 项，50 通过、2 个原生可选检查跳过，耗时 55.523 秒。测试使用临时工作区及可控传输，没有远程模型调用。此前首次异步测试连同原有模型协议测试 18 项通过。

边界：验证了功能隔离、取消、关闭、回执、快照、来源和版本保护；没有声称已测得 p95 调度目标、真实模型提速或费用收益。工具统一注册/handler 迁移、阶段上下文、只读批次持久化及大历史缓存仍待后续批次。

## 第二批：内置工具能力注册表

- 25 个工具的模型、描述、handler、阶段、只读分类与资源通道收敛为不可变内置注册表。阶段过滤读取注册表；执行按注册 handler 分发，不再使用共享 execute 的长条件链。
- 原有 prepare、事务命令、来源过滤与数值 handler 内容保持；未知工具明确拒绝，模型/handler 集合不一致在导入时失败。
- 保留 TOOL_MODELS 只读兼容视图，新增工具不需要修改 Agent 主循环。不引入动态插件加载。

验证：提取前后完整工具 schema 序列化逐字一致；工具命令、代码模块、分析上下文、求解校核与准入定向回归 37 项，35 通过、2 个可选原生检查跳过，耗时 56.333 秒。没有重跑模型 I/O、完整 UI 或完整数值套件。

## 第三批：阶段提示贡献与上下文成本记录

- 公共约束、建模规则、分析规则按阶段组装；模块装配说明仅在模块模式出现。完整旧提示保留为离线基线文本，不再每轮全部发送。
- 首次分析请求可能仍处于建模阶段，因此公共提示始终保留分析入口、物理输入来源和建模不自动授权求解的约束。
- 请求元数据记录提示策略版本、实际 SYSTEM/工具 schema 字符数及各上下文段大小；字符指标不冒充 token。

验证：公共约束、阶段规则、分析上下文、编排与上下文回归共 25 项通过；补充分析入口约束后仅重跑 3 项提示定向检查，全部通过。固定同一简单上下文与工具集合的离线对照：建模请求 34,525 → 30,877 字符（减少 10.6%）；分析请求 26,698 → 21,855 字符（减少 18.1%）。这些是结构性输入减少，不是实际 token、延迟或成功率的 A/B 结果。
