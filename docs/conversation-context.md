## 每次请求

固定系统规则、工程 JSON 与允许调用的工具 schema 分离。当前需求和工程文档必需保留；其余容量分配给完整的近期工具组、长期需求与决策、阶段摘要、相关历史和近期用户消息。各层有独立份额，不再由用户历史先占满整个上下文。metadata.layers 报告容量、使用量与省略条目；完整原文仍在本机。

| 字段 | 含义 |
| --- | --- |
| revision_id / epoch | 本次工程版本与执行轮次，模型请求和工具写入前均检查 |
| statement / statement_source_id | 当前用户目标及原始来源 |
| project | 后端工程文档：几何、材料工况、要求与对象绑定，是当前工程状态的权威 |
| long_term_memory | 有来源的需求、方案和待解决问题；明确被替代或绑定旧几何的记录不作为当前有效记忆 |
| stage_memory | ask_user / finish 成功后的摘录式阶段记录，带来源及原始步骤；不是求解认证 |
| recent_tool_groups | 成功指令与完整回执，注明是否属于当前版本；供应商审计元数据不重复发送 |
| historical_sources | 项目过滤后的 BM25、向量、精确字串混合召回，经开源 cross-encoder 重排、去重和原文展开；明确历史来源及版本 |
| conversation_messages | 近期完整用户消息，带来源、提交版本及显式对象引用 |
| last_tool_rejection | 协议纠正时提供前次拒绝原因和未执行工具的事实 |

当前需求与工程文档固定保留后，其余容量按 40% 工具证据、22% 长期记忆、8% 阶段摘要、12% 历史召回、18% 近期消息分配。单次上下文 60,000 字符、含 schema 的请求不超过 100,000 字符。UTF-8 字节数只报告保守 token 上界，并不是供应商的准确分词计数。这些容量约束不会恢复累计请求、token、活动时间或作业预算。

## 持久化与来源管理

SQLite 保存原始消息、不可变工程版本、步骤、记忆与来源谱系。向量也在 SQLite 持久化；本机 Qdrant 索引可以重建。source 的插入、修改和删除在事务内触发增量索引队列，删除立即清除派生片段与向量。

智能体通过 remember 记录重要需求、决策和问题，必须引用已有来源；通过 supersedes 显式纠正。用户可在“工程记忆与上下文”窗口审阅、纠正或忘记记录。正在执行时先停止再手动纠正，避免旧计划继续使用旧要求。任意自然语言修改仍由智能体理解，并非确定性规则自动识别所有冲突。

阶段结束时自动保存摘录式摘要；重要原生工具回执另外保存带版本的档案。search_sources 可检索，read_source 可分段展开原文。历史计算只能证明记录版本的结果，不能替代当前版本重新验证。遗忘来源会递归清理派生记忆并停止、清除使用过该来源的相关任务回执。已提交工程快照与已导出备份遵循现有保留规则。

工程包包含记忆和原始来源，不包含可重建检索索引。导入仍暂停执行任务，校验来源谱系，并标记来源为导入数据。普通刷新不丢失记录。

## 本地模型与传输范围

嵌入使用 BAAI/bge-small-zh-v1.5，重排使用 BGE reranker v2 m3 的 INT8 ONNX 开源权重。setup_memory.py 下载固定版本并验证哈希；运行时只从本地加载，不调用远程嵌入/重排服务。权重缺失或推理失败时明确报告关键词降级及原因，不能把它称为语义召回。

模型没有默认收到整个几何、完整数值场或工程包；它通过有类型的工具读取接口、拓扑与数值证据。对象引用带 artifact_id、revision_id 和 selection，历史几何引用需要重新选择/绑定；仍未实现自动几何语义映射。相机旋转、悬停和未附到消息的选择不会触发模型请求。

目前每个工程一个持续对话，尚未实现多会话管理；原始对话 GET 尚未分页。早期对话不会自动全部追溯整理为长期需求。记忆过多时仍依靠检索和分层取舍，不能保证每条历史细节始终进入每次请求；被省略信息通过审计与按需工具展开。
