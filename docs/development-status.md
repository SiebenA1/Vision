## 启动与使用

先完成 `python scripts/setup_native.py --fea`，再运行：

```powershell
.python313/python.exe -m pip --disable-pip-version-check install -r backend/requirements.txt
npm run core
# 第二个终端
npm run dev
```

打开 `http://127.0.0.1:4173/`。核心默认监听 8112，数据在 `.vision-workspace`；`--workspace PATH` 可使用独立目录。API 文档为 `http://127.0.0.1:8112/docs`。Vite 的 `VISION_CORE_URL` 可指定其他核心地址。

1. 新建空白工程，填写 USD BRep 脚本并构建。脚本可读取 `parameters`，输出 `result`。
2. 明确选择从空白构建、增量编辑，或按已保存的原始输入重放。重放保留增量脚本的原始源几何，避免重复变换。
   已有几何的修改先点击“检查修改影响”；脚本、参数或版本改变后需重新检查。
3. 在工况编辑器确认材料、支承、合力和网格尺寸，保存后提交分析。界面提供可编辑的工况草稿，未经保存不会生效。
4. 需要语义引用时，在视口选择原生面或从拓扑列表选择，填写名称与用途，保存工程对象。点击出现多候选时明确选择；原生轮廓高亮可用于核对。可将面对象设为唯一固定约束；其他区域可通过工况 JSON 指定。
5. 几何改变后，旧对象保留身份但绑定失效；明确选择新面并重绑定后才能求解。当前不自动推断拓扑对应关系。
6. 填写要求说明和指标阈值。当前支持位移、von Mises 应力、质量上限及屈服安全系数下限；缺失或无效证据返回 `unknown`。
7. 可下载场数组、报告和完整工程包；工程包在空工作区恢复，不执行包内脚本。导入结果标记为历史来源，需当前环境复算后才能参与本地有效判定。

当前 `/` 是统一工程工作区，包含「建模 / CAE 仿真 / 解析校核」三个同级页面。旧 `?workspace=v2` 链接兼容同一入口，不再代表第二个独立产品界面；旧工程仍需显式导入。本文后续批次记录中的历史界面描述，以最新交付为准。

## 第二批：原生选择与资源边界

已加入体/面/边视口拾取、列表与轮廓同步、工程对象绑定轮廓回看。网格交点仅定位查询；身份、裁剪面面积和边长均由保存的原生 BRep 查询确认。多个容差内候选不会按编号或最近距离静默选定，需用户明确选择。面孔洞中心不会被当作未裁剪的无限平面。

新增项目内只读 `/inspect` 接口，强制关联明确的 revision 与 artifact。独立交互通道不进入 CAD/FEA 长作业队列，一次执行一个查询，15 秒超时，争用返回 503、超时返回 504；查询不修改版本。几何或工程切换后，迟到的前端查询结果不能填入当前选择。轮廓最多显示 512 条采样曲线，面积/边长仍为原生计算。

Windows 上新增原生进程树的总提交内存限制：CAD/FEA 默认 4096 MiB，交互查询 1024 MiB。`VISION_WORKER_MEMORY_MIB` 可在启动前设置为 128–65536，任务入队时固定数值，结果保留实际限额。使用 [Windows Job Object 的 JobMemoryLimit](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information)，涵盖后代进程；它限制提交内存，不等同于 RSS 或整个应用峰值。其他平台暂未提供等价硬限额，显式配置该变量时拒绝运行。

本批验证了：真实裁剪面孔洞、角点歧义、体/边选择与尺寸、跨工程/错误制品拒绝、通道争用、超时清理、长 CAD 作业期间查询响应；真实子进程分配超预算内存被拒绝，真实 CAD 内存失败不改变 head，后续小作业仍成功。浏览器使用实际画布点击和原生响应，另延迟真实查询回包后切换工程，确认迟到结果不会串入新工程。

多工程刷新会恢复最近选择的工程；浏览器仅保存该工程 ID 偏好，实际工程存在性、head 和内容均由后端确认。工程 ID 不存在时回到后端列表中的有效工程。

第二批结果：启用真实原生用例的 v2 核心 31 项全部通过；前端 50 项通过；新增画布拾取、迟到响应隔离、多工程重开和完整 CAD/FEA 浏览器回归通过。

## 第三批：编辑恢复与修改影响预检

脚本、参数、构建来源、离散精度、未提交工况和要求可自动保存为本机编辑副本。副本使用 `vision.editor-draft/1`，保留每部分的基础 revision。刷新后通过“恢复草稿副本”显式填回编辑器，不自动提交、不执行脚本、不把旧基础版本替换为最新 head；后端 CAS 继续生效。恢复会展开相关编辑区。

每个页面使用独立 writer ID，按工程隔离保存，多个标签页不会覆盖同一个副本。恢复会生成新的编辑副本，原副本保留；“清空编辑器并保留副本”可收起当前编辑内容，旧副本通过列表手动删除。已提交且不再编辑的工况/要求会从当前活动副本移除。其他页面或历史副本不会被静默清理。

草稿保存在当前浏览器 origin 的 localStorage，不属于后端工程提交，也不包含在工程包中。更换浏览器/站点端口、清除站点数据或使用不保留站点数据的浏览模式时，不能保证继续读取；它不是跨设备备份。单条记录最多 512000 个 UTF-16 码元，存储配额由浏览器决定。写入失败时显示未保存，并撤销当前保存成功提示；已存在的副本不会被当作新内容已保存的证明。损坏、跨工程或未知版本记录不会被恢复，也不会自动删除。

新增只读 `/projects/{id}/build/preview`，输出明确的输入摘要、源几何、待重绑对象、待复核作用区域、分析体选择和证据重算要求。自由脚本的实际输出及拓扑均标记为执行后才可确认；预检不执行脚本，不声称证明脚本无副作用。

工作区修改已有几何时先展示影响，再提交构建。预检与基础版本、脚本、参数、构建来源和离散设置对应；编辑任何一项即失效。提交携带 `expected_impact_digest` 时，后端重新计算摘要，不匹配返回 409，不入队；head 改变仍由 CAS 拒绝。摘要用于防止预检与提交漂移，不是授权令牌。旧 API 调用可省略该字段，仍通过同一入队与版本检查路径。

重放草稿单独保存原始重放 artifact；重新选择基础 revision 不会悄悄更换该来源。缺少来源的旧草稿进入待核对模式，不能按当前几何猜测重放输入。

显式分析体选择新增 `body_artifact_id`，与面绑定一样限定于一个几何制品。几何重建后即使沿用 `body-0` 编号，也会阻断求解；重绑面不等于重新确认分析体。可从原生对象列表选中闭合实体，点击“将所选实体用于分析”明确重新确认，或选择使用全部闭合实体。通过 API 保存显式 `body_ids` 时必须同时提供当前几何的 `body_artifact_id`，不能凭旧编号补造来源；旧格式未记录该字段的选择需重新确认。旧工程迁移只有在 BRep 字节及体顺序均核对后才映射此引用。

第三批验证：32 项 v2 核心测试全部通过，包含带影响摘要的真实参数构建，以及面与分析体分别失效、分别修复后重新求解；前端 13 个文件、52 项测试通过；真实浏览器覆盖三类草稿及参数恢复、旧基础版本保留、跨工程隔离、同源多标签独立副本、清空编辑器保留副本、成功保存后再发生配额失败时撤销保存提示。生产构建与 `git diff --check` 通过；原有 Python 3.12 套件 34 项通过、1 项按环境跳过。

## 第四批：P5 本机任务基础

新增 SQLite 持久任务和逐工具检查点。用户提交原话与明确的 JSON 工具计划；也可从当前 CAD/工况编辑器生成计划后核对。任务由核心服务推进，页面关闭后继续，重开查询同一任务；原生作业仍走已有队列。已提交但未记录检查点的写操作根据固定命令 ID 找回原回执，不重复创建作业。

纠正携带原 epoch 和工程 head；同一事务内递增轮次、取消任务拥有的待完成作业，旧工具在实际写入事务中再次检查轮次。作业写入与检查点之间中断时，也可按原命令回执找到并取消作业。工程变化、工具失败、预算耗尽或明确提问均暂停，不能自动猜测用户答案。最多 24 步、默认 3 个原生作业、单任务上限 8 个作业、最多 8 个活动任务。任务草稿保留其工程基础版本，轮询新 head 不会静默替换。未提交任务表单尚无刷新恢复。

新增项目范围 FTS5 来源检索和本机上下文查看。上下文包含固定版本文档、原话、词法检索来源和完整的近期工具调用/回执组，限制 60,000 字符；字符预算不是模型 token 预算。来源始终标记为陈述，不能代替数值证据。检索使用中文双字词及词法分词，按需重建单项目索引，大历史量性能尚未验证。

“忘记来源”逻辑删除来源及派生来源，停止相关任务，清空这些任务的计划/检查点和 FTS 条目；通过检索回执消费过该来源的任务也停止并清理，检索与删除竞态不会将旧片段重新写入检查点。已提交工程版本、制品和既有备份保留，也不承诺 SQLite 页面取证级擦除。任务用户输入的命令回执只存请求摘要，避免重复保存原话。工程包升级为 `vision.bundle/3`，导入兼容格式 2；活动任务导入后暂停，不能自动执行包内计划。工作区 schema 1/2 升级到 3 前使用 SQLite 在线备份保留原副本。

第四批当时仍无自然语言 Agent。外部模型能力曾因缺少数据外发授权而被自动审批阻断；该批没有发送数据。用户随后明确同意[模型连接范围](model-connection.md)并配置密钥，后续实现见第五批。

第四批验证：32 项 v2 核心测试（含真实原生用例）通过；新增 12 项任务测试全部通过，包含真实 CAD/FEA 服务重开恢复、写后检查点前中断、纠正栅栏、孤立作业取消、跨项目隔离、旧 head 拒绝、活动任务预算、来源副本删除及检索/删除竞态。前端 13 个文件、52 项测试与生产构建通过。原有 Python 3.12 套件 34 项通过、2 项因缺少该运行时的 API 依赖跳过（包含两个 v2 测试模块）。两套真实浏览器回归通过，新增任务场景验证关页继续、原生求解误差小于 2%、来源检索/删除、提问暂停和旧草稿拒绝后显式换基纠正。上述结果证明本机工具协议与恢复行为，不证明真实模型的自动规划质量。

## 第五批：DeepSeek 逐步工具调度

在明确授权和密钥配置后，接入固定 DeepSeek 官方地址。默认 `deepseek-flash` 非思考模式，每轮接收一个函数调用，先保存请求摘要、供应商响应及 usage，再执行现有工具；逐步读取真实回执决定下一步。新增受限原生 API 文档查询，模型构建前必须查询实际接口。密钥仅服务端使用，不进入上下文或原生子进程环境；目标地址固定，不跟随重定向。

模型任务有独立创建/纠正接口和界面模式，保留工程 head、任务 epoch、原生作业预算及来源删除规则。纠正时不能隐式切换本机/模型模式。调用结果不确定、截断、HTTP 错误、无效工具参数、多个工具或重复调用 ID 均暂停，不会自动重试或产生新写入。默认 12 次请求、3 个原生作业，最多 24/8；每次 2,048 输出 token、20 秒网络时限，总预算 250,000 token，10 分钟后暂停后续模型请求；已提交原生作业仍使用其独立超时。模型摘要明确不是数值证据。

来源删除扩展到消费过该来源的模型请求及回执；不能撤回已发送给供应商的数据。schema/工程包升级到 4，打开 1/2/3 前备份，导入兼容包 2/3/4，活动模型任务导入后暂停，绝不自动发送请求。

当前联合回归 52 项通过（32 核心、12 本机任务、8 模型协议/原生工具测试）。真实 DeepSeek 小规模回放已通过：缺失输入场景 1 次请求、0 原生作业后提问（4,150 token）；明确轴向梁场景 6 次请求、2 原生作业完成核验（36,348 token），位移 0.000236425621 mm，对比解析值 0.000238095238 mm，误差约 0.701%。真实浏览器另验证模型任务提交后关页，重开查询到同一提问任务和供应商回执（1 次请求、4,228 token）。各场景为少量合成测试，不据此宣称通用设计质量或发布级任务完成率。协议测试里的测试供应商回执不计入真实模型质量证据。

剩余 P5 验收包括开放式工程任务与失败场景的多轮真实回放、模型费用/延迟基线、旧记忆迁移。当前调度线程顺序等待模型请求，最多 20 秒影响其他任务推进；原生作业控制器和 HTTP 查询独立运行。CAD 仍执行受信本机 Python，不是不可信代码沙箱。

随后在 schema 4 下复验轴向梁时，模型第 3 次请求填入 `body_artifact_id` 却未选择 `body_ids`。后端拒绝工况并暂停，未提交求解；共 15,057 token、1 个 CAD 作业。这是一次真实未完成回放，不计作成功。已在工况 schema 和模型工具说明中明确“分析全部闭合实体时同时省略两个字段”的规则，并纳入无效参数回归；不通过静默修正模型参数绕过校验。

说明修正后的轴向梁回放通过：6 次请求、2 个原生作业、36,896 token，位移和误差与首轮一致，记录包含最终 schema 4 的执行文件摘要及数值包版本。轴向梁本轮共做 3 次独立尝试：2 次完成、1 次因无效工况暂停；不能把修改说明前后的少量样本合并成稳定成功率。[最终回放记录](../screenshots/deepseek-axial-1792803738.json)与[失败记录](../screenshots/deepseek-axial-1792803627.json)保存在本机忽略目录。最终 Python 3.12 兼容套件 34 项通过、3 个 v2 模块按依赖环境跳过。

## 已实现的关键规则

- 每次工程修改带 `command_id`、`idempotency_key`、`expected_head`。重复命令返回原回执；相同 ID 不同内容拒绝；旧 head 修改返回 409。
- 前端保留脚本/工况/要求草稿的基础版本，不以轮询获得的新 head 静默替换提交基础。用户可核对后明确选择以当前版本继续编辑。
- CAD/FEA 提交立即返回持久作业 ID。关闭页面不影响后台计算；停止核心会中断正在执行的工作，待执行作业仍保留。
- Windows Job Object 管理完整子进程树，取消或超时结束后代。重启不盲目重放未知状态任务；已写入完整成功回执的任务先核验再对账。
- 原生计算不持有数据库长事务。制品先发布到不可变哈希目录，成功后提交引用；晚到 CAD 不能覆盖新的 head。
- 求解配置保存实际材料、体选择、载荷、约束、网格设置、实现文件 SHA 和包版本。计算前后核对运行环境，拒绝运行期间发生的实现变化。
- 指标判定核对当前物理输入、最近一次相同输入任务、来源、制品文件完整性、收敛、残差、反力平衡、网格质量和正应变能。同输入最近任务未成功时，不沿用更早成功结果给出当前有效结论。
- 报告固定 revision，记录要求来源、数值证据、运行环境和判定器摘要。要求变化但物理输入未变时可复用匹配证据；工况或环境变化会使旧证据失效。
- 导出通过一致 SQLite 快照收集项目记录和制品依赖闭包。恢复不覆盖已有工程，不执行导入脚本，拒绝损坏文件和越界路径。
- 旧模型保留原始 JSON，不推测对话、版本历史或丢失的结果。只有已核对的原生 BRep 和明确提供的工况才能激活；来源链不全的旧脚本不能伪装成可重放构建。
