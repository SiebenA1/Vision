## 1. 产品目标与范围

VISION 的目标是形成一个持续的工程工作过程：理解需求、形成可操作的工程定义、构建几何、配置分析、获得证据、比较方案、实施修改，并在下次打开时继续。

产品的核心交付对象是一项可恢复、可追溯的设计任务。每个方案应回答：需求来自哪里、采用了哪些假设、针对哪个几何与工况、获得什么计算证据、为何采纳或拒绝。

### 1.1 三个核心发布版本

| 发布 | 用户能够完成的事情 | 发布边界 |
| --- | --- | --- |
| R1：可靠工程工作区 | 保存、关闭、恢复工程；后台任务可追踪和取消；结果与来源完整对应 | 单用户本地，沿用已验证 CAD 和线性静力能力 |
| R2：理解对象与比较方案 | 将要求绑定工程对象；几何修改后核验绑定；比较方案；恢复跨会话 Agent 任务 | 支持选定类别的语义对象；歧义明确交回用户 |
| R3：受约束设计探索 | 指定变量、约束、预算，生成并验证候选方案，采纳后可撤销 | 少量参数、明确边界、现有物理适用范围 |

完整草图、装配、多物理场和多人协作是后续扩展路线，分别有独立的技术验证与发布门槛，不能以 R3 完成为其背书。

### 1.2 贯穿开发的用户场景

S1：新建支架，声明 500 N 载荷、最大位移及不可移动的安装孔，建模并校核。

S2：选中孔声明“用于定位”，下次会话仍能找到来源与对象；改形后不错误沿用失效的面编号。

S3：比较厚度 8 mm 和 6 mm 的方案，明确质量收益、位移代价及尚未满足的要求。

S4：关闭页面后计算继续；重新打开能找回作业与结果；主动取消能终止实际计算进程。

S5：从失败步骤继续，避免重复创建方案、重复提交求解或重复应用修改。

S6：数日后询问“上次为什么加厚，现在能减回来吗”，系统找回理由并针对当前工况重新验证。

S7：将工程导出，在干净工作区导入；无 AI 密钥也能查看保存的几何、工况、证据和报告。

## 2. 当前基线与架构缺口

依据现有代码检查及 [CAE 实测报告](cae-validation.md)，当前已有真实原生 CAD、测量、静力求解、前端失效保护、工程记忆和真实浏览器回归。

| 当前实现 | 可利用的资产 | 对未来目标的限制 |
| --- | --- | --- |
| React / Three.js / Zustand | 视口、拾取、尺寸线、HUD、工况编辑、结果显示 | 工程权威在前端；刷新与多标签操作难以统一 |
| `ModelDocument` 与 localStorage | 工程导入样本、已有设置和脚本 | 显示版本如 R01 没有形成不可变工程提交；结果与聊天恢复不完整 |
| CAD 制品与原生 BRep | 参数重放、增量源几何、测量与导出 | 制品身份不等于工程版本；文件提交与数据库记录无共同事务 |
| `simulation.ts` / `fea_solver.py` | 已验证的直接法、CG、数值证据 | HTTP 同步；取消主要丢弃客户端响应；无持久作业协议 |
| `deepseekAgent.ts` | 工具契约、状态校验、失败分类 | Agent 循环位于浏览器，关闭页面后无法独立接续任务 |
| `agent_memory.py` | 来源、任务意图、FTS5、修订和忘记语义 | 前端提交过渡快照，记忆库不拥有工程 head；实测索引还不完整 |
| 工程 JSON / 几何 ZIP | 兼容性入口 | 不是包含所有依赖、结果与语义的自包含工程包 |

特别需要处理的代码事实：

- `adoptExternalModel` 会保留部分原工况，但 `createExternalModel` 会生成新的设计说明；长期意图不能继续依赖这一段可覆盖的文本。
- `body-0/face-3` 只在所属 artifact 内有意义。保留面编号不能证明修改前后是同一工程对象。
- 当前 `studyFingerprint` 是显示级短哈希；持久作业去重和结果身份需采用后端规范化输入与 SHA-256。
- `variables` / `features` 以及优化相关旧入口不足以构成通用参数依赖图或优化器。
- 现有包导入只读取 USD，不能据此承诺原生 BRep、工况与证据的完整恢复。

## 3. 重写策略与技术决策

### 3.1 推荐：重写应用核心，逐项接入已验证工程能力

| 方案 | 优点 | 主要代价 | 结论 |
| --- | --- | --- | --- |
| 持续修补当前前端权威模式 | 单个页面改动快 | 持久任务、跨会话执行和版本一致性仍需重复补丁 | 不作为目标架构 |
| 重写工程核心，复用或替换边界模块 | 可建立统一事务、作业和证据；保留已有数值验证资产 | 需新旧适配和一次迁移 | 推荐 |
| 连 CAD、求解与视口全部重写 | 内部一致性可重新设计 | 扩大数值与几何回归风险，交付收益未证明 | 仅在模块验证失败时采用 |
| 直接拆成多服务平台 | 可分别部署扩容 | 单机首版增加协调、部署与故障成本 | 远程场景出现后重新评审 |

重写边界按职责划定：

- **重写**：工程领域模型、提交与版本服务、后台作业、结果制品、证据判定、Agent 运行器、应用状态同步。
- **适配后评估保留**：CAD / 测量算法、线弹性求解算法、原生 API 发现、FTS5 检索规则、Three.js 展示组件。
- **替换**：以 localStorage 作为工程真相、前端长任务循环、同步求解主接口、短哈希作为持久身份、旧优化和模型模板提示。
- **保留为兼容数据**：旧工程 JSON、原生制品、来源事件和记忆；不能强制继承旧内部类结构。

首个架构验证必须走通“新核心提交工程 → 原生 CAD 作业 → 求解 → 关闭并重开 → 取回同一版本结果”。若无法成立，应在 P0/P1 改结构，而非继续堆功能。

### 3.2 目标技术组合

| 层 | 建议 | 取舍 |
| --- | --- | --- |
| 前端 | React + TypeScript + Three.js；Zustand 仅保存界面和草稿状态 | 渲染能力可复用，工程事实来自后端 |
| API 与领域核心 | Python 3.13，FastAPI + Pydantic 严格请求模型 | 替换手写路由与分散校验；统一契约生成 TypeScript 类型 |
| 关系存储 | 标准库 SQLite，单个本地 workspace 数据库 | 短事务、显式迁移；首版无需 ORM 与网络数据库 |
| 大型制品 | 本地内容寻址文件库，数据库保存清单和引用 | BRep、网格和结果数组不塞入对话或关系行 |
| 执行器 | 持久队列表 + 单控制器 + 原生子进程 | 计算并行度与 CPU / 内存预算明确控制 |
| CAD / CAE | 独立 ABI 运行时与 worker 协议 | CAD 3.12、CAE 3.13 可继续使用；不让 Web 进程直接加载原生内核 |
| Agent | 后端持久任务状态机，供应商适配器 | 首先支持现有 DeepSeek；工具协议独立于供应商 |
| 前后端事件 | 首版轮询作业状态；随后 SSE 可恢复事件流 | 不以 WebSocket 或消息中间件作为首版前置条件 |
| 检索 | 结构化依赖过滤 + FTS5 | 向量检索由跨表述召回评测决定 |

新增 Web 契约依赖有明确收益：严格请求校验、错误结构与 OpenAPI 可以减少多端契约漂移；具体版本在 P0 原型通过后锁定，不在规划阶段宣称已经安装。FastAPI 的异步端点仍需把重计算移到 worker，不能把 `async` 当作数值并行。[官方并发说明](https://fastapi.tiangolo.com/async/)、[严格校验说明](https://docs.pydantic.dev/latest/concepts/strict_mode/)。

## 4. 目标架构与权威边界

```text
工程工作台 / Agent 对话 / 对比视图
                |
        统一 API 与命令校验
                |
   工程版本 ─ 作业 ─ 语义与要求 ─ 证据与判定
                |
     SQLite 工作区 + 内容寻址制品库
                |
     后端任务运行器 / 原生作业控制器
          |                  |
     CAD worker          CAE worker
```

以上是同一应用内的模块边界，不要求微服务拆分。

### 4.1 五条必须成立的不变量

1. 后端拥有已提交工程版本；前端草稿不得自行成为当前工程事实。
2. 每个计算产物绑定不可变输入、运行环境和算法版本，历史成功不自动成为当前证据。
3. 用户声明、系统解释、原生测量、求解结果、工程判定分别存储和展示。
4. GUI 与 Agent 通过同一命令服务修改工程，不能有绕过校验的“内部快速入口”。
5. 重试、迟到响应、崩溃恢复和取消都不能悄悄覆盖新的工程 head。

### 4.2 工程版本与事务

工程提交包含 `projectId, branchId, parentRevisionId, revisionId, schemaVersion`，并引用几何、材料、工况、要求和对象绑定的具体修订。`revisionId` 使用不可变 UUID，内容摘要另存 SHA-256。R01 仅为显示标签。

首版支持主线历史和命名候选分支；不做自由文本式的 BRep 三方合并。恢复历史以新提交引用旧状态完成，不修改过去的提交。短时输入草稿与持久工程版本分开保存，避免每次键入产生正式版本。

命令使用 `expectedHeadRevisionId` 做比较并交换。事务中同时写入命令回执、工程提交、分支 head 与领域事件；不在数据库写事务内等待 LLM、CAD 或 FEM。长计算返回候选产物，采纳时再验证 head。冲突返回 409 和差异说明。

语义变化不必重算物理场：例如修改最大允许位移，只重做判定；修改载荷、几何或材料的计算输入才使对应求解证据失效。几何、求解、判定三个依赖键分开定义。

### 4.3 数据库与文件的一致性

SQLite 事务不能与任意文件写入构成一个原子事务。因此采用：临时目录生成 → 校验文件及哈希 → 在同文件系统原子发布完整清单 → 短数据库事务引用该制品。崩溃后可能留下未引用制品，由恢复扫描识别；不得留下指向未完成文件的成功记录。

制品发布需要解决同摘要并发发布与 Windows 文件替换行为，采用唯一 staging 目录和串行提交/原子发布；不能直接复用当前共享 `manifest.tmp` 写法。GC 必须经过保留期、引用闭包检查和备份检查，首版默认不自动清理历史。

工作区数据库部署在本机。SQLite WAL 支持读写并发，但仍只有一个写事务，且不适用于跨机器网络文件系统；因此写事务必须短，重计算不占连接。[SQLite WAL](https://sqlite.org/wal.html)、[事务说明](https://sqlite.org/lang_transaction.html)。

以下为目标逻辑实体，不要求每项从第一阶段起独立建表；先实现各阶段实际需要的实体。

| 实体 | 关键内容 | 权威来源 |
| --- | --- | --- |
| Workspace / Project / Branch | 稳定身份、工作区版本、分支 head | 后端提交服务 |
| ProjectRevision | 父提交、模型/工况/语义引用、作者和原因 | 不可变工程提交 |

| Job / JobAttempt / JobEvent | 输入摘要、状态、执行所有者、心跳、产物及错误 | 作业控制器 |
| AnalysisArtifact | 网格、结果数组、边界证据、残差、环境、日志引用 | CAE 成功回执 |
| SourceEvent / RequirementRevision | 原文、来源、作用范围、规范化命题与修订关系 | 用户来源及规则校验 |
| SemanticObject / BindingRevision | 稳定语义身份、artifact 拓扑绑定、绑定依据及有效状态 | 建模谱系或已确认选择 |

| DesignAlternative / Decision | 候选版本、比较基线、取舍与采纳理由 | 用户操作或授权策略 |
| AgentTask / Step / Checkpoint | 用户目标、执行状态、未决项、工具回执引用 | 后端 Agent 运行器 |
| SearchRun / Candidate | 搜索范围、预算、候选输入、结果及可行性 | 优化调度器 |

### 5.1 单位、哈希和版本

- 内部保持 mm、N、MPa、kg 等既有约定，密度与惯性显式带单位；接口数值与单位分离。先支持有限明确的换算，不让 LLM 自由算单位。
- 拒绝 NaN、Infinity、布尔冒充数值、零方向、越界材料参数及未知 schema；工况占位值标为未确认，不能直接作为“需求已定义”。
- 规范化 JSON 规定键排序、浮点/零值处理、集合与有序数组语义；规范化算法自身有版本。
- 计算身份包含原生内容、离散精度、参与体、材料数值、物理模型、边界、网格、求解配置、内核及算法版本。
- `resultHash` 验证产物字节完整性；物理复现按容差比较，不能承诺不同硬件重算出逐字节相同结果。
- 同输入重算创建新的 attempt，缓存复用保留原 run 引用；命令幂等与计算缓存是两个独立概念。

## 6. 后台作业与故障恢复

### 6.1 状态与调度

作业状态：`queued → running → succeeded / failed / cancelled / timed_out`。取消处理中可为 `cancelling`；崩溃无法判明时标为 `interrupted`，不伪装成数值不收敛。

首版一个本地控制器，SQLite 持久队列；CAE 并行度默认 1，交互测量与 CAD 使用独立受限队列，预留交互能力。多进程 Web 部署时不得各自启动控制器，先采用单 Web 进程配置和控制器独占锁。

原生适配器直接调用单次计算 worker 协议，不能在新控制器里再嵌套旧 `solve()` 的调度和全局槽锁。首轮保留已验证的 `_solve_impl` 数值逻辑；调度、进程控制和文件协议由新核心接管并重新回归。

作业受理事务保存完整输入及待执行状态。控制器在短事务中认领 attempt，然后释放数据库锁运行子进程。worker 完成后原子写回执；控制器校验产物后发布成功。任务可以成功但不适用于最新 head，界面应显示其历史归属。

### 6.2 幂等、取消与重启

- 相同工程、操作和幂等键、相同参数返回原回执；同键不同参数返回冲突。
- 队列中的取消直接终止调度；运行中的取消先记录意图，再终止进程树并等待退出，最后确认状态。
- 首版“恢复计算”指复用已完成作业，或创建新 attempt 从头执行；不承诺 CAD 内核栈或 CG 迭代现场续算。
- 浏览器刷新不影响后台作业。服务重启先核对 worker 回执、产物、进程实例与 attempt 身份；不能只看 PID，以免复用到其他进程。
- 无法确认是否已完成的非幂等操作进入 `interrupted/needs_review`，不盲目重复执行。工程采纳通过 CAS 与唯一回执去重，实现一次采纳，不能声称任意外部执行 exactly-once。
- 明确服务退出策略：主动停止先停止 Agent、取消原生作业并落盘；异常退出由进程托管机制清理，重启按持久状态对账。

Windows 首先验证 Job Objects 的进程树管理与关闭清理，并测试父子进程启动/加入过程的竞态；Python `Popen` 负责句柄和 I/O。Job Objects 能管理关联进程组，但不等于任意脚本安全沙箱。[Python 3.13 subprocess](https://docs.python.org/3.13/library/subprocess.html)、[Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。

### 6.3 事件、进度与资源

持久事件包含递增序号、实际阶段、时间、日志引用；前端可从序号重连。阶段包括建模、离散、网格、组装、求解、后处理。无可测进度时仅显示阶段与耗时；CG 迭代次数不冒充完成百分比。

定义 CPU、内存、运行时间、队列长度与磁盘预算；现有生成后单元上限保留，但不能当成网格生成峰值内存限制。内存估算只作准入参考，硬限制需验证原生库失败与清理路径；超限不得回写成功结果。

## 7. 语义对象、参数与 CAD 修改

### 7.1 稳定语义身份

`semanticObjectId` 表达“安装孔 A”“定位面”，独立于面列表序号。一个对象可绑定多个面/边；绑定记录带 artifact、拓扑对象、坐标系、选择规则与来源。导入几何允许先由用户选中并命名，不要求自动识别所有特征。

绑定依据优先级：受控操作记录中的明确谱系 → 经验证的命名选择器 → 几何/邻接候选。第三类只提供重绑定候选；模糊匹配分数再高，也不能自行作为载荷或接口约束的有效绑定。

状态为 `bound / needs_rebind / ambiguous / missing`。几何重建时，比较形状类别、尺寸范围、位置/轴线、邻接与语义约束；即便谱系存在，也要验证目标仍满足该角色定义。多候选必须展示差异并让用户选择。

### 7.2 两条建模通道

脚本通道保留通用表达能力，保存完整输入和源制品谱系。受控参数操作通道逐步引入有类型操作，如生成实体、孔、加强筋、阵列；操作节点具有参数与依赖，支持重放、失败定位和参数搜索。

首版只对实际支持的操作建立依赖图；任意 Python 脚本作为 opaque 节点，不能自动逆向成完整特征树。需要可靠搜索的参数必须声明类型、单位、范围、制造/几何约束和重建方式。

修改流程为：固定基线 → 生成候选 → 检查接口要求和几何有效性 → 处理绑定 → 生成对比 → 按用户当前授权采纳。常规已授权且可撤销修改可自动采纳；出现歧义、约束冲突或超预算才暂停，不增加逐操作确认。

原生操作有消耗/原地修改对象的所有权规则；worker 适配器和回放测试必须覆盖。官方最新文档仅用于核对机制，运行时仍以已安装版本的反射和真实测试为准。[USD BRep API](https://nvidia-omniverse.github.io/usd-brep/latest/docs/python.html)。

## 8. 要求、证据与工程判定

### 8.1 要求不是自由文本标签

结构化要求包含目标对象、谓词、值、单位、上下限或公差、适用工况、来源与修订。声明“500 N”时必须区分需求载荷、当前工况值和历史分析输入。未给定的位移/应力门槛保持未定义，不能套用界面默认值作为验收要求。

复杂自然语言先保存原话与候选命题。确定性校验可检查引用、单位和条件是否存在，但不能完全证明 LLM 没有曲解用户；因此以歧义回放评测、用户可见的简短任务理解和纠正机制共同控制。

### 8.2 证据与判定分离

Evidence 由后端工具回执创建，包含 geometry/study/runtime/measurement-method 的依赖以及误差含义。LLM 只能引用证据 ID，不能提交一段“已测量”的文字创建 verified 证据。

Assessment 对某条要求返回 `pass / fail / unknown / not_applicable`，附采用的证据、方法与限制。缺失公差、失效对象、失败作业或未支持的物理产生 unknown，不能等同于 pass。

例：“孔径要求 10 mm”与“测量 9.98 mm”是要求/观测之差；未给公差时不能自动认定合格。定位用途也不能推导出粗糙度或配合等级。

### 8.3 CAE 验证升级

沿用当前轴向、弯曲、载荷叠加、原生面、空腔和流道基准。增加：相同已保存网格上直接法/CG 对比、刚体模态拒绝、负方向与区域边界、单位缩放、近不可压缩材料适用性、病态网格和故障取消。

相同网格求解器对比先作为内部测试入口，不强制对用户开放求解算法选择。CG 对刚度系统的条件有要求；算法成功码、自由 DOF 残差、反力平衡和位移解析误差分别检查。[SciPy 1.15.3 CG 契约](https://docs.scipy.org/doc/scipy-1.15.3/reference/generated/scipy.sparse.linalg.cg.html)。

网格加密首先服务于用户选定指标；三档以上趋势、实际自由度及边界选区一致性共同记录。位移稳定不能推出应力稳定。接触、奇异应力和复合材料等超出当前物理模型时明确限制结论。

## 9. 方案比较与决策记录

方案是工程版本引用与评估集合，不复制整套文件。对比页显示几何变化、质量、载荷/约束、材料、网格策略、位移、应力、余量与计算状态。

对比先检查可比性：相同需求、物理模型与工况；几何不同则边界必须按相同物理语义正确重绑定；网格需要满足一致的精度策略，不要求不同形状有相同单元数。不可比时标记具体原因，仍可查看原始结果。

采纳写入新 head、基线和候选引用、采用理由及证据列表。撤销是可追溯的新版本；历史方案仍可查看。“为什么加厚”从决策与回执找到来源，不能让 LLM 从当前形状臆造历史。

## 10. 后端 Agent 与工程记忆

### 10.1 执行状态机

目标流程：保存原始发言 → 编译当前上下文 → 形成任务理解/未决项 → 选择工具 → 统一命令校验 → 等待作业 → 更新证据 → 解释或进入下一步。

任务状态为 `created / planning / executing / waiting_job / waiting_user / completed / failed / cancelled`。每次工具前后保存检查点、命令 ID 和回执；页面只订阅任务状态，不持有唯一执行现场。

用户中途纠正时递增任务 epoch：停止旧计划继续提交，保留已完成产物；新步骤以最新工程 head 和新要求编译上下文。已发生但无法撤销的外部副作用不属于首版 Agent 工具范围。

停止生成、取消当前作业、取消整个搜索/任务在 UI 与协议中区分；必须清楚说明哪些结果已保存、哪些后续步骤未执行。

### 10.2 上下文和记忆

复用现有“声明有来源、实测来自工具、FTS5、完整工具交互组、修订/忘记”的语义，重写其与后端工程版本的连接。已有字符预算在新实现中显式标为字符；供应商 tokenizer 可用后才宣称 token 预算。

上下文包含当前版本、任务、相关要求与冲突、对象绑定、当前证据、近期对话及历史来源引用；完整脚本和场数组按需获取。主对话和智能测量共用编译服务，各有权限与预算。

原始来源、决策和有效证据可以持久化；不保存隐藏推理作为长期知识。长期经验只有带适用条件与验证版本的记录才能召回，默认不跨项目传播工程约束。

遗忘语义明确为删除选定来源及派生检索/摘要/会话内容；历史工程文件中已提交的设计数据单独显示范围，不能声称来源删除就自动清除了所有制品或用户备份。新旧实现保持同样诚实的删除说明。

### 10.3 供应商与密钥

LLM 适配器负责流式协议、工具消息、用量、错误及兼容会话。换模型不直接重放不兼容推理/工具协议。API 密钥保留在服务进程或显式本地凭据配置，永不写入工程包、事件及日志。业务正确性不依赖某个特定模型名称。

持久 Agent 依赖后端 LLM 请求路径；生产入口由后端服务提供静态文件和 API，Vite 仅用于开发。不能继续要求浏览器保持打开才能完成任务。

## 11. 受约束参数搜索

首版以 1–3 个连续/离散参数、明确取值边界、明确单一目标及硬约束为范围。例如最小质量，同时保持安装孔位置、位移上限与材料适用条件。

执行前固定基线版本、参数映射、对象绑定、工况、精度策略、允许次数/时长与失败预算。先用确定性网格/分层采样或有界一维搜索；多维有限采样可记录非支配候选，但不宣称全局最优。只有真实评测证明收益后才增加贝叶斯或演化算法依赖。

每个候选顺序执行：重建 → 几何/接口约束 → 绑定验证 → 测量筛选 → FEM → 有效性及约束判定。几何失败、物理不适用、求解失败与约束不满足分别归类。缺证据的候选不能排名为可行最优。

候选不改变主分支。完成后显示“本次预算内已验证的最佳候选”和搜索覆盖；根据用户明确给定的自动采纳策略或当前选择采纳。停止后保留有效候选；需求变化时冻结旧搜索，不能继续用旧目标消耗预算。

## 12. 用户界面与交互交付

保留模型与视口为中心的工作台，逐步加入任务状态、版本历史、候选比较和要求检查，不强制展示数据库/Agent 内部名词。

| 入口 | 主要行为 |
| --- | --- |
| 工程中心 | 后端工程列表、保存状态、恢复/导入、历史版本 |
| 模型与选择 | 原生拾取、语义命名、参数、失效绑定修复 |
| 要求摘要 | 当前任务目标、来源、未决问题；可自然语言纠正 |
| 作业面板 | 实际阶段、耗时、取消、失败解释、日志详情 |
| 分析结果 | 当前/历史归属、物理适用性、数值检查、需求判定 |
| 方案对比 | 同步相机、数值差异、可比性、采纳和理由 |
| 搜索面板 | 变量/目标/约束/预算、候选状态和停止 |
| 报告 | 要求—证据—结论链、版本、环境、限制和可下载制品 |

界面必须区分：已保存与本地草稿、当前有效与历史结果、用户要求与系统假设、计算完成与要求满足。首版保留 Markdown 报告；HTML/打印 PDF 在结构化内容稳定后增加。

## 13. API 与建议代码组织

### 13.1 对外契约草案

统一前缀 `/api/v2`；工程修改带 `commandId / idempotencyKey / expectedHeadRevisionId`。作业取消、任务停止等独立操作使用对应资源状态版本，不因工程 head 已前进而拒绝取消旧作业；创建资源时引用明确的父版本。

| 接口组 | 草案能力 |
| --- | --- |
| `/projects`、`/projects/{id}/revisions` | 创建、列表、读取提交与历史 |
| `/projects/{id}/commands` | 修改材料/工况/要求、提交候选、恢复版本；统一命令入口 |
| `/jobs`、`/jobs/{id}`、`/jobs/{id}/cancel` | 提交、查询、取消；提交返回 202 与作业引用 |
| `/jobs/{id}/events?after=` | 可重连的阶段与日志索引；首版普通 JSON，后续 SSE |
| `/artifacts/{id}/manifest`、`/artifacts/{id}/files/{name}` | 制品清单与二进制读取 |
| `/projects/{id}/objects`、`/bindings` | 语义对象、绑定与重绑定候选 |
| `/projects/{id}/requirements`、`/assessments` | 要求、来源和判定查询 |
| `/projects/{id}/alternatives`、`/comparisons` | 候选方案与可比性 |
| `/projects/{id}/tasks`、`/tasks/{id}/messages` | 持久 Agent 任务、纠正与状态 |
| `/projects/{id}/searches` | 有界搜索及候选；内部仍走同一作业系统 |
| `/projects/{id}/export`、`/imports` | 完整工程包与迁移预检 |

旧同步 CAD/FEA 接口只在迁移期由适配器提供，内部统一提交作业；不得保留可绕过 head 和证据校验的第二套写路径。

### 13.2 建议模块结构

```text
backend/vision/
  api/              请求模型、路由与事件订阅
  domain/           工程、工况、要求、对象和判定
  storage/          SQLite 迁移、事务与制品库
  jobs/             队列、执行尝试、恢复与进程控制
  workers/          CAD / CAE 协议及适配器
  agent/            任务状态机、上下文与供应商适配
  exploration/      方案比较与参数搜索
  migrations/       旧工程和记忆的只读导入
src/
  api/              生成的契约类型与客户端
  features/         工程、模型、任务、分析、比较
  state/            界面状态与草稿，不再维护第二份工程 head
```

目录随阶段创建，不一次性生成空框架。原 `server/*.py` 可先由适配器调用；通过契约回归后再迁移代码归属。只有出现真实性能或维护问题时才重写数值算法。

工期为一名熟悉 Python、TypeScript 与 CAD/CAE 的工程师有效人周估算，包含该阶段必要测试和文档，不包含后续独立物理求解器项目。阶段目标与验收优先于周数。

每个工作包交付代码、契约、对应失败回归、变更说明和验收记录。阶段验收未通过时修复或收缩范围，不能用截图和模型自述代替真实工具记录。

| 顺序 | 任务 | 具体交付 |

## 15. 迁移、兼容与回退

### 15.1 迁移输入与步骤

旧来源包括浏览器工程 JSON、`.cad_artifacts`、记忆 SQLite 与可识别的 `.fea_runs`。浏览器数据通过当前客户端显式导出/提交给迁移入口，后端无法直接读取任意浏览器 localStorage。

迁移步骤：只读扫描 → 生成带数量/缺失项的迁移报告 → 使用 SQLite backup API 建立一致副本 → 导入新 workspace staging → 验证来源和制品闭包 → 激活新工作区。保留原始数据及 migrationId/sourceDigest，重复导入不得重复生成工程。

旧 `projectId + modelId` 映射到稳定新身份，保留映射表。旧事件 ID、来源关系与 supersedes 链保留；缺失外部来源明确标记。旧 R01 不当成真实提交序列。未保存的聊天、修改理由和求解字段不能从脚本反推补造。

旧结果只有在请求、输出、算法/环境与几何能够核验时导入为带来源的历史证据；否则作为 legacy-unverified 文件保留，不纳入当前判定。旧几何 ZIP 仍走几何导入，不伪装为完整工程恢复。

### 15.2 切换方式

开发期新核心独立运行，旧应用只读导出；以功能开关选择工作区。完成切换后后端为唯一权威，前端 localStorage 只保留布局/偏好和待恢复草稿，不维持双写当前工程。

每个工作区同一时刻只允许一个已激活核心写入。回退恢复到切换前备份或导出可兼容副本；新格式中的分支、语义和结果不得声称可无损降级到旧 JSON。

## 16. 完整工程包、备份与留存

新包使用版本化 manifest，声明项目、提交、来源/要求、决策、绑定、研究、结果、runtime 和所有文件哈希。默认不包含密钥、API 隐藏推理或全局配置。可选择仅几何、工程不含结果、完整工程三种导出，但范围需在 UI 明确。

完整包包含所选提交的依赖闭包：增量脚本的源 BRep、网格与结果数组、相应材料数值和可追溯来源。导入优先恢复原生制品；跨内核版本无法加载时仍保留原件，并允许显式转换为新的制品与修订。导入绝不自动执行包内脚本。

SQLite 与制品不能只在不同时间各复制一次就叫一致备份。导出/备份先固定所选 revision 与引用集合，通过 backup API 得到元数据快照，再复制该快照引用的不可变文件并校验；备份期间固定 GC 保留引用。[SQLite backup API](https://sqlite.org/backup.html)。

首版按用户操作备份，P8 加入可配置的本地定期备份与失败提示。恢复演练必须在空目录完成。留存、来源删除与外部已导出包的范围明确说明，删除派生索引不等同于删除用户已有备份。

## 17. 验证矩阵与发布质量门槛

| 层次 | 主要验证 | 通过条件 |
| --- | --- | --- |
| 领域/存储 | CAS、事务、schema 迁移、幂等、来源与依赖 | 相同命令不重复采纳；旧 head 写入必冲突；无悬挂成功引用 |
| 故障注入 | 任意提交边界中断、worker 崩溃、磁盘满、损坏文件 | 重启可对账；当前 head 可读；错误分类准确 |
| 作业 | 取消前/中/后、超时、重启、同时提交 | 进程树清理；任务不被误标成功；旧作业不覆盖新版本 |
| CAD / 测量 | 现有 13 类操作、裁剪孔、质量、截面、参数重放 | 真实内核回归；几何/单位/引用正确 |
| 拓扑绑定 | 排序改变、孔分裂/合并、消失、对称多候选 | 不错误自动绑定；需要重选时明确阻断依赖操作 |
| CAE | 现有解析基准、相同网格 direct/CG、残差/反力、空腔/多体 | 分项阈值通过；不以成功码代替数值验证 |
| Agent | 来源理解、纠正、断线、供应商切换、未知工具状态 | 不重复副作用、不伪造实测、不使用失效要求 |
| 对比/搜索 | 可比性、预算停止、候选失败、需求变更 | 不可行/未知候选不进入已验证最佳；主版本不被污染 |
| E2E | S1–S7，刷新、关闭重开、导出导入、窄屏 | 真实 CAD/CAE 主线通过；页面无未捕获错误 |

Agent 验证分两组：可控 LLM 的确定性协议/故障回归，以及小规模真实模型任务回放；前者不能证明真实模型规划质量，后者需记录模型、预算和重复次数。既有 60 条工程回放构想先落成去重且覆盖失败条件的数据集，不按用例数量冒充质量。

必须零容忍的类别是串项目、伪造工具证据、错绑后静默施加载荷、未核验结果采纳和已提交数据丢失。发现即阻断相关发布。一般任务完成率、延迟与成本设独立目标，P0/P5 先测基线再固定阈值。

性能目标均为待验证：在记录硬件、样本和制品尺寸后，给非计算 API 的 p95、恢复首页时间、结果下载/首帧、取消确认时间及峰值内存建立预算。可暂以普通元数据 p95 300 ms、无场数组的工程恢复 2 s、取消进程确认 5 s 为原型目标，若平台不满足需明确修订，不当成当前能力。

## 18. 后续全部构想的独立扩展路线

核心 R1–R3 不预先实现空插件系统；出现第二种实际能力时再抽取稳定接口。各扩展先做可否成立的原型和基准，批准范围后另排实施工期。

| 扩展 | 前置条件与具体实现方向 | 原型验收 / 决策门槛 |
| --- | --- | --- |
| 草图与完整特征依赖 | 参数操作协议稳定；评估现有内核或外部约束求解器，建立自由度、过约束和失败回放 | 至少覆盖直线/圆/尺寸/几何约束、欠约束与过约束；无法可靠求解则不宣称通用草图 |
| 装配与运动关系 | 稳定部件身份、局部坐标系、变换及实例关系；再加入配合约束与冲突诊断 | 两部件定位、轴孔同轴、干涉及欠/过约束；装配配合不自动产生 FEA 接触 |
| 多材料/实体扩展 | StudyRevision 可表述每体材料；优先独立部件工况，再评估显式绑定界面 | 分层/分段解析对比与界面连续性，材料映射不丢失 |
| 壳/梁 | 厚度、截面、方向、转动自由度及网格映射；选择有支持的数值路径 | 板/梁解析基准和壳实体对照；片体存在不等于可做壳分析 |
| 模态/屈曲 | 质量矩阵、特征值或预应力基态及约束定义 | 梁频率/Euler 屈曲和刚体模态；单独处理特征值收敛 |
| 接触/塑性/大变形 | 非线性求解与接触算法评估，载荷步、材料状态及一致切线 | 接触斑、塑性单轴、路径/步长与能量平衡；不能在当前线性求解器上添加标签完成 |
| 复合材料/疲劳 | 铺层方向与本构、失效准则；循环载荷和寿命模型/材料数据 | 试样/层合板与标准算例；材料名称不得替代参数与适用条件 |
| 热/流体及耦合 | 独立物理工况与边界体系，优先适配成熟求解器，再考虑网格映射 | 热传导、压降、守恒及耦合收敛；流道几何成功不代表 CFD 完成 |
| 向量召回与经验 | 先标注跨表述检索数据；结构化过滤后增加 embedding/RRF 等候选方案 | 相对 FTS5 基线显著提升召回且不增加来源/版本错误；无收益则不部署 |
| 协作/远程计算 | 身份、权限、传输认证、远程 worker 隔离、对象存储、作业租约和服务化数据库 | 两用户并发冲突、隔离、审计、撤销访问、故障恢复；本地任意 Python 执行不能直接外网开放 |
| 更强优化/生成设计 | 有足够失败分类和预算评测；评估代理模型、贝叶斯、多目标或拓扑优化 | 与简单采样同预算比较；代理预测经真实工具复验后才能采纳 |

每项先安排约 1–2 人周的范围原型/选型验证；原型周期不包含正式求解器集成和工程验收。非线性、复合材料和多物理场需要相应领域人员，不能给出缺少基准与目标规模的统一总工期。

## 19. 风险、停止条件与取舍

| 风险 | 控制措施 | 停止或改变路线的条件 |
| --- | --- | --- |
| 重写范围失控 | 每阶段必须交付端到端切片；旧系统只作兼容来源 | P0 无闭环则重评数据契约，不继续生成框架 |
| 内核缺少稳定拓扑谱系 | 显式语义绑定、受控操作和人工重选 | 对称/分裂对象无法消歧时关闭自动绑定 |
| 自由脚本难以可靠参数化 | opaque 脚本节点 + 明确参数协议 | 无可靠变量映射时停止该搜索，不伪造特征树 |
| 原生进程/内存故障 | 独立 worker、实际进程树、预算、故障回归 | 清理失败或结果污染则阻断后台任务发布 |
| 数值模型超适用范围 | 物理预检、基准、残差/平衡/收敛分开报告 | CG 不收敛或证据缺失则失败；不静默换物理模型 |
| LLM 误解来源或重复执行 | 用户原话、任务 epoch、统一命令、幂等回执 | 未决歧义影响几何/工况时暂停相关步骤 |
| 文件/DB 双写损坏 | staging、不可变发布、事务引用、恢复扫描 | 发现成功记录缺制品则阻断导出/判定并修复 |
| 迁移丢历史 | 只读输入、备份、来源映射、差异报告 | 不可核验结果只迁为历史附件，不归入当前实测 |
| 单机到云的信任边界变化 | 独立远程发布路线，鉴权与执行隔离先行 | 无隔离方案则不发布共享远程执行 |

## 20. 计划完成定义

规划层面已明确目标、重写边界、技术依据、数据模型、执行与恢复、语义和证据、对比与优化、迁移、阶段依赖、工期假设、验收和远期路线。

实施开始从 P0 进入。R3 的完成定义是：在真实内核和求解器支持的物理范围内，用户能够跨会话完成需求定义、对象修改、方案比较与有预算搜索，保存和解释完整决策证据，并在故障后恢复。它不意味着工业 CAD/CAE 全能力已被覆盖。
