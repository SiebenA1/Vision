# 工程管理与模型配置

2026-10-24：在唯一工作台 `/` 的顶部提供独立“工程管理”“模型配置”窗口，持续对话与三维视口仍为主界面。旧组件直接依赖浏览器旧 store，因此迁移的是功能与交互，而非将旧 store 接到新后端。

## 工程管理

- 新建：名称去除首尾空白并校验，创建后直接打开。
- 打开/切换：显示后端已保存工程，支持名称搜索；切换后分别恢复模型、版本、对话和本机草稿。
- 重命名：新窗口要求工程任务与作业空闲，使用 expected_head 防止覆盖其他页面更新；兼容旧 API 默认允许乐观版本变更的行为。
- 导出：工程包包含版本、对话、作业和依赖制品；已有几何也可直接下载 USD。
- 删除：第一次点击“删除”只展示工程名称、数据范围和第二次确认。确认后先停止任务及实际原生作业，等待作业终止，再提交永久删除。服务端再次校验名称、head 与运行状态。无回收站或恢复操作。

永久删除清理工程、历史版本、对话来源/索引、任务步骤、作业/日志和关联命令回执；删除本机浏览器中的对应对话与编辑草稿。其他工程仍引用的几何、结果及其源依赖保留；只清理不再被引用的目标工程制品。未采纳但具有目标版本 provenance 的输出也纳入清理。已导出的工程包与历史备份不受影响，不承诺磁盘取证级擦除。

几何制品缺失不阻止工程记录删除；文件无法清理或依赖损坏时明确返回警告。文件删除前验证路径处于 artifacts/runs 的直接子目录，不沿符号链接或目录联接删除。记录先提交删除，清理失败不会使半缺文件的工程重新出现。

新增接口：POST `/projects/{id}/stop`、POST `/projects/{id}/delete`；重命名沿用 POST `/projects/{id}/rename`，窗口传入 `require_idle=true`。删除请求必须有 confirmed_name、expected_head 和幂等命令身份。

“打开”当前指打开本地后端保存的工程。旧工程 JSON 迁移和完整包恢复仍在高级工具中；完整包恢复仍要求空工作区，未在本次变更中实现多工程工作区中的包合并。

## 模型配置

显示后端密钥是否配置、DeepSeek 模型选择与保存，以及实际服务地址/执行协议说明。设置保存在工作区 `model-settings.json`，仅包含模型名称，通过原子替换保存；覆盖该工作区的环境变量模型默认值。密钥仍仅从后端环境或根目录 .env 获取，不显示或导入旧浏览器存储的密钥。

模型选择用于新任务和下一条对话；已执行任务继续使用已固定的模型。累计预算继续禁用。旧版思考模式、流式、温度等选项尚未迁移为可调参数，当前执行协议仍使用非思考、非流式工具调用；窗口如实显示固定配置。

GET/POST `/model-settings`，写入模型限定为当前支持的 deepseek-flash、deepseek-v4-pro。
