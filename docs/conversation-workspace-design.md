# VISION 对话工程工作台设计与实施计划

日期：2026-10-24。状态：待实施设计。独立 HTML 原型现已撤下，产品只保留 `/` 一个工作台入口，后续能力直接在此实现。

本文更新总体计划中的交互、Agent 会话与预算设计。已存在的工程核心继续作为权威数据源；此文不表示以下能力已经实现。

首版落地更新：`/` 已接入真实持续对话与模型分栏、后端消息恢复、多轮需求和回执上下文、显式原生对象引用、停止/替换执行。暂采用每个工程一个会话，复用现有来源与检查点表，不新增独立 sessions/messages 表。按用户要求暂不启用累计预算。长期摘要、多会话、参数拖拽等仍未实现；具体上下文实现与局限见 [上下文说明](conversation-context.md)。

## 1. 产品工作方式

用户通过持续对话提出、澄清和修改工程需求，通过模型视口指明对象；Agent 将语言和对象引用转成有类型的工具指令，调用本地工程服务，并依据实际回执继续工作。用户无需编写工具 JSON、选择任务类型或人工拼接建模与求解流程。

工程是长期容器；一个工程可有多个会话，一个会话可包含多个执行任务。会话保留用户意图和解释，任务保留执行检查点，工程版本保存实际修改。不能把每条聊天消息直接等同于一次全新任务，也不能把模型的自然语言回复当成执行结果。

示例：用户要求创建支架 → Agent 询问缺少的尺寸和载荷 → 用户回答 → Agent 建模 → 用户选择两个孔并说“保持这两个孔的位置，把底板减薄到 6 mm” → Agent 验证对象引用、预览影响、修改 → 用户说“按之前的载荷再算一次” → Agent 读取已保存工况、检查绑定并求解 → 用当前证据回答。

## 2. 新界面

桌面默认采用左侧约 360–440 px 对话区、右侧占据剩余空间的模型视口。顶部只显示工程名称、保存/连接状态，以及工程、历史、导出和设置入口。对话和视口各自滚动或固定，不再把视口、任务表单和调试信息纵向堆叠。

| 区域 | 常驻内容 | 按需出现 |
| --- | --- | --- |
| 对话区 | 会话消息、简短执行状态、固定输入框、停止按钮 | 澄清选项、阻塞原因、预算续跑卡、执行结果卡 |
| 模型区 | 几何、选择高亮、旋转/缩放/平移、适应窗口、选择类型 | 选择浮条、测量、剖切、结果显示与图例 |
| 上下文栏 | 输入框附近的对象引用标签，可逐个移除 | 引用详情、来源版本、失效提示 |
| 详情抽屉 | 默认关闭 | 工况与要求、版本历史、对比、任务步骤、证据和高级设置 |

移出主界面：脚本编辑器、工具计划 JSON、任务执行方式、模型请求次数、原生作业数量、编译上下文、供应商回执、内部任务 ID。保留这些能力的高级入口以便排错、审计和专家操作；不能通过隐藏信息丢失可追溯性。

用户始终能看见当前是否在执行、是否需要补充、是否失败、能否停止，以及显示结果属于哪个版本。空工程首屏直接提供需求输入和少量示例，不展示大片空视口加禁用按钮。模型生成后以视口为主要工作区域。

窄屏改为“模型 / 对话”两个视图，保留选中对象标记和执行状态；不把完整工程表单放在聊天之前。键盘可访问、可调整分栏、足够对比度和独立滚动属于验收范围。

## 3. 持续对话与执行

1. 发送消息时，保存原文、发送时工程 head 和附带对象引用，再创建或推进执行任务；回车发送，Shift+回车换行。
2. Agent 可回答、询问或调用工具；正常的解释性回答无需强制包装为工程工具。进入执行时，每一步仍接受工具契约、版本和预算校验。
3. 执行期间允许继续输入。补充说明可进入等待队列；改变当前执行目标的消息在下一安全边界使旧计划失效。后台不能并发修改同一工程 head。
4. 对正在运行的原生作业，界面区分“先停止当前作业并调整”与“等本次完成再执行”。停止请求与实际进程退出分别显示，不能收到取消请求就宣称已经停止。
5. Agent 的澄清作为普通对话出现；用户回答后沿用会话和任务背景，无需载入纠正草稿。
6. 刷新或重开后从后端恢复消息、活动任务、预算状态和对应工程版本；前端缓存只存未发送草稿。

初期仍可使用现有轮询同步。先实现消息与任务事件持久化，再根据延迟与流量引入 SSE；不以流式文字效果阻塞主流程交付。

## 4. 模型直接操作与 LLM 上下文

### 4.1 选择和对象引用

支持单选、追加多选、清空、切换面/边/实体、从对象列表定位，以及点击空白取消。选择后显示对象名称与简短测量，浮条提供“添加到对话”“测量”“设为约束”“施加载荷”等入口。后三者生成带对象引用的待发送意图或经过校验的参数卡，不绕过工程命令服务。

选中只改变本地视图，不自动发起模型请求。点击“添加到对话”或发送“这个面……”等含当前选择的消息时，将清楚可见的引用标签与消息一并提交；鼠标悬停、转动相机不触发 API 调用。首版允许自动附带当前选择，但必须在发送前可见、可移除。

建议引用格式：

```json
{
  "kind": "topology_selection",
  "project_id": "...",
  "revision_id": "...",
  "artifact_id": "...",
  "entity_kind": "face",
  "entity_ids": ["body-0/face-3"],
  "semantic_object_ids": [],
  "pick_point_mm": [0, 10, 5]
}
```

客户端传递意图和引用；后端验证工程、版本、制品归属及对象存在性，读取可信名称、尺寸和法向等摘要。不能接受客户端自称的几何事实。精确点可辅助解释，不能替代稳定的原生身份。

同一面在不同制品中的 ID 相同不代表同一对象。几何更改后旧引用必须显示失效；优先通过已有语义对象和绑定机制解析。无法唯一确定时让用户重新选择，不能按最近距离静默绑定。

### 4.2 编辑的边界

第一阶段提供选择、定位、测量和引用；第二阶段提供面向对象的工况/要求参数卡；第三阶段才提供参数尺寸与变换手柄。

任何拖拽只产生预览；提交时形成带单位、坐标系、源版本的工程命令，成功后生成新版本并写入对话事件。Esc 取消预览。后台版本变化时预览失效。Undo 指向实际工程版本恢复，不是只回退画面。

目前 CAD 核心主要使用脚本构建，不具备通用参数特征历史。只有后端明确声明可编辑的参数或变换才显示手柄。任意面拉伸、拖动孔位、特征重建和约束草图必须另行验证 CAD 能力后实现，不能用网格变形冒充原生几何修改。

### 4.3 上下文编译

每次模型请求按需编译：当前目标和约束、近期完整消息、可信工程文档、当前版本摘要、该次消息携带的对象引用、相关工具回执，以及检索的历史来源。长期摘要保留来源 ID 和版本，不能把推测升级为事实。

选择事件和直接编辑事件进入会话时间线；发送给模型的是有版本身份的对象摘要与工具查询结果。相机视角仅在用户明确要求视觉解释时使用，不默认发送截图、网格、BRep 或完整数值场。新增几何属性摘要仍需更新现有数据范围文档；未来视觉上传需单独提供明确的发送入口。

工程事实来自服务与制品，需求来自用户消息，历史来源与模型解释分别标明。模型响应到达时再次校验任务 epoch 与 head；用户已改需求或模型时，晚到的写入指令不能落地。

## 5. 预算与复杂任务续跑

采用总 token、原生作业、累计执行时间和请求次数的组合预算；请求次数是较宽的兜底阈值，不再作为默认 12 步的产品流程。最终默认数值由复杂任务回放测量后确定，设置界面提供普通/复杂任务预设及自定义，避免未经验证地承诺“无限执行”。

软阈值显示实际消耗和剩余计划；硬阈值在安全边界暂停。预算不足卡片只提供“增加预算并继续”“调整目标”“停止”。继续只增加上限，从检查点恢复；保持已用量、原 epoch、既有回执和幂等身份，不清零成本，不重放成功步骤。修改目标才进入新执行 epoch。

时间计量累计活动执行时间并分开记录网络与原生作业时间；等待用户或预算补充不应消耗活动时间。请求返回结果不明仍必须暂停处理，不能借续跑重复发起；对明确拒绝的多调用响应保留现有一次纠正路径，且计入总量。

无进展检测使用规范化工具名、输入、源版本和回执指纹：相同查询、相同错误或无修改的重复构建达到阈值后，要求 Agent 改策略或询问用户。查询新对象、不同参数试验及迭代求解不应单凭请求次数判定循环。

## 6. 实现边界与接口

复用现有 React/Three.js、原生拾取与查询、SQLite 工程提交、任务检查点、数值证据、DeepSeek 传输及已验证的 CAD/FEA。重写主布局、任务表单交互与会话驱动层；不同时重写数值算法或另建一套工程状态真相。

建议在现有 SQLite 内增加 sessions、messages 及 session_events，工具执行仍使用 agent_tasks/agent_turns，消息通过 task_id 关联执行。会话消息追加保存；补充、撤回或删除通过明确事件处理，并沿用来源忘记机制清除派生摘要和检索索引。工程包升级时包含会话与事件，兼容旧包；导入不自动执行未完成任务。

建议接口（尚未实现）：

| 接口 | 职责 |
| --- | --- |
| POST /projects/{id}/sessions | 新建持久会话 |
| GET /sessions/{id}/messages?after= | 增量恢复消息与分页历史 |
| POST /sessions/{id}/messages | 幂等保存消息、expected_head、附带对象引用和意图 |
| GET /sessions/{id}/events?after= | 增量同步执行状态、工程更新、选择失效与结果 |
| POST /tasks/{id}/continue | expected_epoch/head、预算增量与检查点续跑 |
| POST /sessions/{id}/interrupt | 明确中止或替换执行目标，协调作业取消 |

现有 correct-model 保留兼容，普通用户界面不再暴露“纠正草稿”协议。新增状态需区分 awaiting_input、budget_paused、failed、cancelled，与 executing/waiting_job/completed；不能继续将全部原因塞入 waiting_user 和一段字符串。接口返回结构化 reason_code、可用操作和下一步说明。

## 7. 分阶段开发与验收

| 阶段 | 实施内容 | 必须通过的验收 |
| --- | --- | --- |
| A：会话与续跑协议 | 会话/消息/事件、状态原因、预算增量、检查点续跑、迁移与包兼容 | 预算耗尽后原地继续；不清零已用量、不重建任务、不重复 CAD/FEA；重启可恢复；不确定请求不重发 |
| B：新工作台主界面 | 对话 + 模型分栏、固定输入框、执行卡、详情抽屉、工程切换 | 无工具 JSON 即可从需求到建模；窄屏可达；真实鼠标滚动和键盘操作；刷新、多标签、工程切换无串消息 |
| C：选择进入上下文 | 引用标签、后端对象验证、歧义处理、消息引用落盘与编译 | 选面说“这里固定”只绑定所选面；多选、旧版本、历史消息、跨工程和失效 ID 均有回归 |
| D：持续协作执行 | 追问、补充消息排队、目标替换、原生作业取消协调、无进展检测 | 运行中改载荷不采纳旧回执为新结论；旧 epoch 不能写入；重复消息不重复执行 |
| E：对象操作与结果 | 工况/要求卡、测量、结果定位、版本恢复；可编辑参数能力验证后接入手柄 | 直接操作写回同一工程并被下一轮 LLM 识别；历史结果明确标注；求解数据与实际版本一致 |
| F：复杂场景验收与迁移 | 长任务回放、预算预设测量、现有工程升级、新界面成为默认入口 | 简单梁、带孔支架、多实体及至少一次失败恢复/预算续跑；报告真实成本、耗时与未支持能力 |

A 与 B 先交付最小闭环；C 紧接其后。以真实用户操作验证“说一句话 → 建模 → 选择对象 → 追问修改 → 求解 → 关闭恢复”，不以静态页面、模拟聊天或成功 HTTP 响应代替工程验收。

## 8. 当前原型与交付区别

此前的 HTML 原型已完成交互评审并撤下；原型链接及旧 `?workspace=v2` 链接统一进入 `/`。单入口当前连接真实工程核心，新对话界面和协议按上述阶段直接在该工作台实现；统一入口不代表所有设计能力已经交付。
