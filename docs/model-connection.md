# v2 DeepSeek 模型任务

用户已明确授权按下列范围接入 DeepSeek，实现现已启用；原先的审批阻断已解除。本机显式计划仍可独立使用，不需要密钥。用户可在任务面板查看“本机编译上下文”，本次查看本身不向外发送。旧工作台的模型连接与此功能分开。

在“持久任务 → 任务计划与来源”选择“DeepSeek 模型任务”，填写说明并启动。界面显示数据范围、模型、密钥状态和预算。任务检查点可展开查看供应商响应 ID、工具调用 ID、usage 和请求摘要。载入原输入可提交纠正；旧轮次迟到响应被丢弃，提问、错误或预算到达时暂停。

## 连接与发送范围

目标固定为 DeepSeek 官方 `https://api.deepseek.com/chat/completions`，不接受任意目标地址、不跟随重定向、不使用环境代理。按[官方接口文档](https://api-docs.deepseek.com/api/create-chat-completion/)使用非思考模式与函数调用，每次只接受一个完整工具调用。默认模型 `deepseek-flash`，后端 `VISION_DEEPSEEK_MODEL` 可切换为 `deepseek-v4-pro`。

密钥读取后端进程 `DEEPSEEK_API_KEY`，未设置时读取仓库根 `.env` 的同名字段，不进入工程包、上下文或日志，也不传给 CAD/查询子进程。Windows 用户环境变量更新后应从新终端启动核心，旧终端不会自动继承。旧网关的 `DEEPSEEK_API_BASE` 不改变 v2 的固定地址。

模型模式发送的数据限定于当前工程任务：

- 用户当前任务原话及纠正、固定工程版本的文档：工程名、几何制品引用、材料、载荷、约束、网格设置、要求与语义对象绑定。
- 当前项目检索到的历史来源片段，保留来源 ID 与来源性质；不检索其他项目。
- 近期完整工具调用及回执，包括数值摘要、错误和后端核验结果。模型陈述不产生数值证据。
- 模型明确请求读取脚本时，发送当前几何脚本的有限片段，单次不超过 8,000 字符；生成脚本和相关工具参数也属于后续对话内容。

传输实现不上传 BRep、USD、STL、数值场数组或完整工程包，不主动读取任意本机文件，不发送 `.env`、密钥或其他项目数据。CAD 脚本仍沿用现有受信本机 Python 执行边界，不是不可信代码沙箱。选择模型模式启动任务意味着允许模型使用当前工具修改工程；所有写入仍经过现有版本检查和原生队列。

## 当前对话执行设置（2026-10-24）

按用户要求，持续对话及新建模型任务默认 `unlimited=true`，不执行下文历史版本的累计请求次数、总 token、总时长和原生作业预算检查；保留实际 token 记账、单次请求容量、独立网络/作业超时、取消、幂等及 epoch/head 校验。旧已暂停任务不会因此自动重放。当前会话上下文见 [上下文说明](conversation-context.md)。

## 检查点与预算（早期受限任务兼容设置）

每轮最多一个执行工具调用（同轮相关 CAD 文档查询可合并）、16,384 输出 token、180 秒网络总时限，响应最多 256 KiB。启用 thinking，默认low；明确的复杂分件初始规划或构建失败修复可提高为high。各次请求独立装配精简的工程上下文，不回放不完整的 assistant/tool 推理历史，不保存原始 reasoning_content。参数依据 [DeepSeek thinking 文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

思考模式的工具选择使用 `tool_choice=auto`；DeepSeek 不支持在此模式使用 `required` 或强制指定工具，否则返回400。一次一个工具由系统指令、响应校验和一次协议纠正执行，不依赖不受支持的强制工具参数。HTTP错误仅输出分类后的诊断，不回显服务端原始错误体中的密钥或工程内容。

有界模式默认最多12次请求、3个原生作业，总预算250,000 token，10分钟后不再发起新请求；纠正轮次重算预算。界面当前默认 unlimited，跳过上述累计预算，但仍执行单次响应、工具参数、版本及协议校验。模型上下文24,000字符，全请求100,000字符。发送前按 UTF-8 字节数和输出上限保守预留 token，成功响应按 usage 记账；网络结果不确定时不会自动重发。输出截断、未执行的无效工具有一次协议纠正机会。实际进入队列才计原生作业，参数拒绝不计作业。

请求摘要先落盘，再调用供应商；通过协议和参数检查后保存供应商响应及规范化命令，再执行工具。重启时请求结果不确定则暂停，不自动重试。工具已提交但检查点未完成时，根据固定命令 ID 找回原回执。HTTP 错误、超时、多工具响应、截断内容、无效参数和重复调用 ID 均不产生新的工程写入。原生 API 查询在受限查询通道执行，模型建模前必须先查询实际接口。

多工具响应有一项明确例外：完整响应及 usage 校验通过后，记录 `rejected` 检查点和实际 token 用量，拒绝其中所有调用；下一轮最多发起一次协议纠正请求，明确告知模型上一轮没有执行任何工具。纠正仍占用原有请求、时间和 token 预算。连续第二次多调用则暂停，不继续重发。供应商调用 ID 按不透明、有长度限制的可打印标识处理，不以函数名称的字符规则校验。HTTP 错误、超时及其他无效响应不进入此纠正路径。

2026-10-24 参数校验反馈更新：对已通过供应商响应校验、且属于本轮提供工具的调用，Pydantic 参数错误也记录为 `rejected`，不执行工具，将字段位置、错误类型和说明作为 `last_tool_rejection` 反馈给模型。错误不复制 input_value 或 Pydantic 外链；连续两轮协议/参数拒绝则暂停，不无限重试。未知字段仍严格拒绝，不静默丢弃。已验证 `native_api(suggest_query="boolean")` 被拒绝后，真实 DeepSeek 改为合法的 `query="boolean"` 并完成原生接口文档查询。

`list_topology` 按页列出当前几何的原生 ID、包围盒和指标；`inspect_geometry` 用于测量已知 ID/查询已知点，不接受空查询。工况使用独立的 `configure_study`，包围面选择器不需要查询 CAD 建模 API。已有当前核验且之后没有构建、工况修改或求解时，下一请求不再提供重复核验工具；新求解后恢复该工具。供应商回执记录实际请求耗时。

来源删除也会停止并清理消费过该来源的模型任务。它只处理本机记录，无法撤回已经发送的数据；已提交工程、制品和既有备份仍保留。

## API、升级与验证

模型创建接口为 `POST /api/v2/projects/{project}/model-tasks`，携带命令身份、`expected_head`、`statement`、`max_jobs`、`max_requests`。纠正为 `POST /api/v2/tasks/{task}/correct-model`，额外携带 `expected_epoch`。查询和停止沿用任务接口；纠正不能隐式切换模型/本机模式。

工作区 schema 和工程包版本现为 4。升级 1/2/3 前在线备份；工程包兼容导入 2/3/4，活动任务导入后暂停，不能自动发送请求。旧核心拒绝新工作区/包，避免把模型任务误当成空显式计划。
