# 工程 Agent 记忆：首批实施说明

日期：2026-10-20。对应设计报告阶段 A/B，以及 C 中的会话检查点和执行状态基础；不代表设计报告的全部发布门槛均已验收。

## 使用方式

前端没有记忆管理面板，用户无需看到或操作记忆。正常在 ATLAS 对话中提出要求、追加条件或纠正即可。记忆在 LLM 调用路径内部运行。

每轮先保存不可改写的用户消息与当时的选择。Agent 使用 `update_task_intent` 维护有来源的任务理解：new、continue、revise、cancel、clarify。归一化目标标为 agent_interpretation，不当作用户额外确认。对历史的承接必须引用本工程真实事件 ID。未维护本轮意图、存在未决问题或任务已取消时，程序阻止依赖该意图的工程操作。

`remember_engineering_intent` 保存重要工程要求，内容必须逐字来自本轮用户消息，并使用后端 sourceEventId；作用对象只允许本轮选择或工程范围。模型自行生成的尺寸、用途推测不能通过该工具入库。用户明确修订时，通过 supersedesId 建立替代关系而不覆盖原文。无法确定哪项生效时通过普通对话澄清，不要求用户管理记忆表。

`withdraw_engineering_memory` 仅响应本轮明确的撤回或忘记要求。需要无歧义的任务理解与来源。给原生对象记录的用途始终绑定 artifactId；重建后旧用途不自动套到同编号面上。

主聊天与智能几何解读共用 ContextService。主聊天读取工程记忆；几何解读读取工程级与当前选中对象的记忆。用途声明不会创造粗糙度、公差或密封性能数据。解读只规划测量，数值仍由真实内核按测量项编号查询。

## 持久化和隔离

- 默认数据库：`server/.agent_memory/memory.sqlite3`，已加入 Git 忽略；可用 `VISION_MEMORY_DB` 指定其他本地路径。
- 工程作用域使用已持久化的 projectId/modelId 组合，不使用可改名的工程编号。当前是单用户本地应用，不宣称具备多用户身份认证或跨租户 ACL。
- HTTP schema 为 `vision.memory/1`，数据库 user_version 为2，WAL 与短事务；升级会补建全文索引，检测到更高 user_version 时拒绝旧程序覆盖。
- 快照保存几何标识、材料、设计说明、工况和拓扑索引，不复制脚本、STL 或网格。当前模型仍由前端工程状态管理；每次请求登记不可变快照，尚未迁移到后端工程提交权威。
- 主聊天固定规则位于 system，工程快照和记忆位于数据消息；每次成功工具执行后刷新当前状态。
- 目前不把事件中的工具返回值提取成长期实测记忆，也不从聊天文本生成实测记录。现有原生制品、测量 API 和求解结果有效性检查仍负责工程证据。

## 会话和任务

已完成的同模型/思考模式会话，可以在刷新后的下一次发言中恢复 API 历史。历史按完整 user/assistant/tool 交互组保留，最多约 40,000 字符；不是按消息条数裁剪，也不把字符数当作实际 token 数。

工程记忆修改后，旧版本会话不再直接重放；换模型或未完成任务只传目标、回答摘要和状态，不强行复用不兼容的工具/推理协议。原始 assistant 文字明确标为对话内容，不能成为实测；只有成功执行记录进入有效输出块，且要再次校验几何、材料、工况版本。

每次调用包含稳定规则、最新工程快照、当前任务理解、适用要求、近期完整交互与成功工具输出，并按本轮问题检索早期来源。原始记录在库中保留，进入上下文的是有引用的精选内容，不是持续拼接所有历史。

工程语义检索预算为主聊天 10,000 字符、几何解读 6,000 字符。使用对象作用域、主题排序与 SQLite FTS5 中文双字全文检索，未引入 embedding；相关冲突不能因预算被静默丢弃。`search_engineering_history` 可扩展查询，`read_engineering_source` 分页取回完整原始事件，截断节选均带标记。已移除本轮消息总长 180,000 字符的本地硬拦截；本轮工具协议及思考内容保持完整，由服务端执行模型实际上下文容量限制。历史召回预算不是精确 token 预算。

内核接口通过 `/cad/api-index` 提供已安装内核的实际符号目录及顶层函数签名，直接加入工程上下文。目录由真实内核反射生成，在后端进程内缓存，并保存到 `server/.cad_api/index-<fingerprint>.json` 便于检查。前端每轮通过 ETag 条件请求确认目录版本；完整签名按目录指纹、查询和页码缓存，指纹变化时清除。同轮重复查询返回已提供文档的引用。需要详细重载或所有权说明时按准确 symbol 查询，不再依靠多轮宽泛关键词摸索接口。工具轮数上限为 32，耗尽时明确报告任务未完成，不把接口查询当作建模成功。本地任务异常不会标记 LLM 连接失败或触发本地规划器回退。

工具执行保留 started/succeeded/failed。中断后没有完成记录的工具显示 unknown，继续时不能自动重放该工具。这里没有宣称跨进程 exactly-once：原生作业查询与幂等作业协议仍待后续实现。

## 修订与忘记

内部更新采用预期 memory revision，冲突返回409；原有记录不会静默被新记录覆盖。修订、撤回、忘记也使正在显示或生成的几何解读失效。不通过前端表单修改记忆。

用户在对话中要求「忘记」后，清除该来源正文与派生记录、保存的旧会话检查点、上下文缓存和全文索引，并清除可能含转述的非用户执行事件。其他独立来源的用户声明保留。当前调用也会清除旧 API 历史，避免下一轮把已删除来源再发回 LLM 或写回检查点。工程模型、设计说明及当前界面聊天文本不因此改写。

导出为 JSON（包含该工程的记忆、来源与任务记录），不是自动附入现有 CAD 工程包。首版不自动导入别处的记忆，也未开启自动到期删除或备份调度。备份与留存策略仍需后续显式落地，不能仅复制正在写入的 SQLite 主文件就声称完成备份。

## 失败方式

存储或接口不可用时，不假装已召回历史；程序阻止无法核对历史要求的 agent 工程操作，说明本次操作未执行。独立原生测量界面可继续使用。记忆发生并发变更时，在下一次工具调用前重新校验，拒绝依赖旧版本继续操作。

后端需要加载新增 `/memory/*` 接口。`GET /health` 返回 `memory_schema: vision.memory/1` 可确认版本。

## 验证

- `npm run test:agent-memory`：SQLite 持久化、隔离、来源验证、修订、冲突、失效、忘记、会话兼容、未知执行状态。
- `npm test`：包括历史工具配对、字符预算、快照不含脚本/网格、存储失败行为和原有前端回归。
- `npm run test:agent-memory-ui`：隔离数据库 + 真实内核 + 受控 LLM，验证无记忆界面的自动任务维护、聊天声明、刷新恢复、材料修改、几何解读共享意图、真实面积，以及自然语言忘记后不再发送原始来源。
- `npm run test:smart-inspection-ui`：原有按需测量与选择切换回归。
- `npm run test:measurement-ui`：基础原生测量、拾取、截面、材料与透明 HUD 回归。

浏览器测试使用合成模型，拦截所有 LLM completion 请求；不会发送用户工程到外部 AI。构建和上述测试通过不等于设计报告中 60 条工程回放、性能目标和全部长期运行门槛已完成。
